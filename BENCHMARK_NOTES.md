# Experiment Design and Limitations

## Objective

Study how a size-based routing rule changes the distribution of token processing across an expensive parent and cheaper worker, and whether lossy worker summaries retain all information required by a synthetic task. The experiment **does not measure a language model**.

## Corpus

Four generated Java-like fixtures per seed, roughly 520, 640, 410 and 80 lines. Every file carries `// FACT: ...` annotations used as known ground-truth labels. There are nine task templates per seed: normal single-file and cross-file questions, small file, security review, concurrency review, exact edit, and boilerplate generation.

Five seeds create 45 task instances per scenario. Seed changes filler and file sizes, not the ground-truth facts, so these are **not independent statistical replicates of model behavior**. Do not use the seed spread to claim confidence intervals for model performance.

## Systems compared

- `direct`: route all requests to an idealized parent fact oracle.
- `threshold-150`: only noncritical bulk reads over 150 lines delegated.
- `threshold-350`: same at 350 lines.
- `threshold-700`: same at 700 lines.
- `no-risk-guard`: allow some otherwise critical/boilerplate tasks to delegate, but `reasoning` and `edit` categories still remain with parent by category rule.
- `shorter-worker-summary`: threshold 350, limit worker to one annotated fact per file instead of three.

## Worker and baseline

The direct oracle collects all annotated facts from a file. The synthetic worker takes the first `cap_per_file` facts, preserving order and removing duplicates. It performs no semantic parsing, code execution, or LLM generation. As a result, the quality score is **labeled fact recall**, not accuracy or correctness of generated code. This artificial asymmetry is deliberate and must not be advertised as a real-world Claude versus Gemini result.

## Token accounting

`token_proxy = ceil(UTF-8 bytes / 4)`.

Parent direct input = corpus proxy + question proxy + 100 fixed overhead.
Parent delegated input = worker summary proxy + question proxy + 100 fixed overhead.
Parent output = 128 fixed tokens for either route.
Worker delegated input = corpus proxy + question proxy + 75 fixed overhead.
Worker output = summary proxy.

Every route's parent and worker counts are recorded and aggregated. Prices per million tokens are fixed hypotheticals, not verified vendor prices: parent input $3, parent output $15, worker input $0.30, worker output $1.20.

Synthetic latency = two seconds direct or fourteen seconds delegated, independent of corpus size. This is not measured latency. No cache accounting, retries, tool calls, or multi-turn history.

## Five-seed results

Source of truth: `results/benchmark.json`, generated by:

```bash
python3 -m shunt_lab.benchmark --seeds 5 --output results/benchmark.json
```

Main threshold-350: 41.64% fewer parent tokens, 1.18% more total tokens, 33.69% modeled cost reduction, 94.7% required-fact recall.

Removing the risk guard and enabling worker writing: 66.55% fewer parent tokens, 1.81% more total tokens, 53.87% modeled cost reduction, 89.5% required-fact recall.

Worker one fact per file: 41.77% fewer parent tokens, 0.91% more total tokens, 33.86% modeled cost reduction, 63.2% required-fact recall.

At 700 lines, the fixtures do not trigger bulk delegation, so all metrics match direct baseline.

## Validity threats

1. The files are generated, not a real repository or benchmark of code intelligence.
2. The labels are known in advance and syntactically obvious; the direct oracle is perfect by design.
3. A first-three-facts worker is intentionally lossy and not an actual model.
4. The fixed output-token assumption does not reflect different answer lengths or retries.
5. Prices are illustrative and may not match current offerings or negotiated rates.
6. The 1:4 byte proxy does not equal provider tokenization, especially for code and non-ASCII text.
7. Task seeds perturb file size and filler, not model response randomness.
8. The routing function uses explicit `critical` labels that the original plugin hooks do not infer.
9. Reported latency is an assumption and cannot support claims about performance.
10. The shell hook simulator approximates common paths and must not be used for authorization or sandboxing.

## What a faithful real-world evaluation would add

Paired real repository tasks, frozen code snapshots, model identification and version, mode ID, strict usage fields including cached tokens, measured latency percentiles, external billing reconciliation, reference answers, compile/test/mutation checks, severity-weighted defect recall, repeatability across independent runs, and complete traces of fallback.
